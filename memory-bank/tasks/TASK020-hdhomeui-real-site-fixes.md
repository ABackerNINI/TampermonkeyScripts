## 6. 窄屏扫描（视口 1366 / 1280 / 1024 / 900）

真站验收脚本支持 `HDUI_VW=<宽>` 覆盖视口（用 `Emulation.setDeviceMetricsOverride` 锁定 ——
headless 下只给 `--window-size` 不等于布局视口）。四档扫描在**每个宽度下都是全无**。
文档宽：1366→1351、1280→1265、1024→**1157→1140（上妆后反而更窄）**、900→1140，均未被撑宽。

**入口胶囊是否完整落在视口内**（`inView`，判据是右边缘是否超出 `innerWidth`）：

| 视口 | 入口 x | 右边缘 | inView |
|---|---|---|---|
| 1366 | 1078 | 1228 | ✓ |
| 1280 | 1035 | 1185 | ✓ |
| 1024 | 880 | 1030 | ✗ 超出 6px |
| 900 | 756 | 906 | ✗ 超出 6px |

⚠️ **已知小限制（不改）**：≤1024 时入口胶囊右边缘超出视口约 **6px**
（150px 宽的胶囊仍可见 144px、可点）。根因是导航 `max-width:100vw` —— **`100vw` 含滚动条宽度**，
所以总是溢出那么一点；但这个上限又是必需的（P46：换 flex 后不给上限，窄屏时后面的入口会排到视口外）。
权衡结论：**不动** —— 修它有可能把「导航换行」这个已修好的问题带回来，而收益只有 6px；
且站点本身就是固定宽布局，≤1024 已经要横向滚动了。

## 6d. `.23` 顺手补回被压平的状态线索（P63）

修完进度格后回头验证底色，发现一处**自己早先埋的 UX 回退**：

- 站点原本**用底色区分**进度状态：做种 = 青 `#44cef6`、下载 = 粉 `#CC0066`
- 但 `.14` 的 `td[bgcolor]{background:var(--hdui-panel)}` 把两者压成了**同一个深色**
  ⇒ 两种状态长得一模一样，**只剩文字能分辨**

**为什么漏了这么久**：`#CC0066` 亮度约 73、`#44cef6` 约 161，**都不在漏白扫描的门槛（>200）内**，
扫不出来。（教训：**"不是白底" ≠ "没问题"**，中等亮度的语义色块要单独量。）

**修法**：底色压平后用**文字颜色**把线索补回来 —— `translateLeeching()` 在替换文字时
顺便给格子打 `data-hdui-prog="seed"|"leech"` 标记，CSS 按标记染字色：
做种 = 绿 `#7fb84e`、下载 = 琥珀 `#f5b342`。

三个实现要点：
1. **认原词，别认替换后的中文** —— 标记要在替换**之前**判定，否则重复调用
   （结构守卫会重试）时中文已经不是英文，认不出来。
2. **必须连 `font` / `b` 一起染** —— 站点在 `<font color="#fff">` / `<font color="#FF0066">` 上
   写死了 color，只染 `td` 会被子元素声明盖掉。
3. 用 `data-*` 标记而不是 `td[bgcolor="#44cef6"]` 选择器 —— **认词语比认站点配色稳**。

真站验收：3 个做种格 `prog=seed` 字色绿、1 个下载格 `prog=leech` 字色琥珀，
4 个格子底色都已压成深色（lum 22）。

## 6e. `.24` 新增「中间带亮块」扫描，抓到 hover 态的提示框（P63/P64）

P63 的教训是"不是白底 ≠ 没问题"，所以新增一档：**中间带亮块**（背景 lum **60~200**）
—— 补漏白扫描（>200）够不着的那一截，语义色块常落在这一段。

扫出两处：
1. `span.tags` 的 23 种分类色 → **白名单**（TASK019 用户拍板刻意保留，深色底上唯一的彩色元素）
2. **`div.niceTitle`（DomTT 提示框）** 背景 `#7c98ae` 亮蓝灰 + 黑字 → **真漏网，已修**

第 2 处最值得记：它平时是 `visibility:hidden`，**hover 才显示** ——
而漏白 / 小件近白 / 对比度 / 文本截断**全都只扫"此刻可见"的元素** ⇒
隐藏元素永远不在视野里，但它一 hover 就在深色底上亮一块（P64）。
顺带把论坛的 `div.smilies td`（同一个 `#7c98ae`）也深色化了。

**教训**：渲染扫描的覆盖面 = "此刻可见"。**hover 态 / 弹层 / 提示框 / 折叠面板一律测不到**，
只能主动按选择器查（在真站 `querySelector` 出来，哪怕此刻 hidden 也读它的
`background-color` / `color`）：读到站点原色（`#7c98ae`）= 漏了，读到主题色（`rgb(25,21,18)`）= 已覆盖。

白名单另一条：主题金 `rgb(245,179,66)`（当前页高亮 / 做种数这类刻意强调色）。

八档扫描现状：CSS 存活 255/255、中间带 / 漏白 / 小件近白 / 残留装饰 / 对比度 / 文本截断**全无**。

### P64 再推广：把"查隐藏元素"做成**第 9 档「全量背景色」扫描**

不再逐个猜选择器，而是扫 **body 下所有元素（不管可见与否）**，凡 `background-color` 的 lum ≥ 40
就按颜色归并报出，并标注 `vis`（此刻可见数）—— **vis=0 的就是纯 hover / 隐藏态漏网**。
排除自持 UI（`#hdui-root`）与 `span.tags`（刻意保留的 23 分类色，数量多会淹没其它发现）。

**结果**：排除标签后**只剩 1 项** —— 主题金 `rgb(245,179,66)`（当前页高亮，刻意设计）。
⇒ **种子页上所有背景（含隐藏 / hover 态）都已被主题覆盖，没有站点残留色了。**
