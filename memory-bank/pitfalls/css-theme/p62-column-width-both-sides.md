> 摘要: 列宽类规则必须片头 + 数据行两边都写 —— 只写一边会在窄屏错位（宽屏看不出来）；片头与数据行是两条独立的 flex 行。
> 触发: 列宽规则, 片头数据行两边, hSel, 窄屏错位, 多视口复验

- **触发**: .21 多视口复验时发现：1024 视口下列 [1]（标题）表头 256px、数据行 240px，后面 11 列整体左移 16px；1280 / 1366 视口下却完全对齐。

## P62. 列宽类规则必须**片头 + 数据行两边都写** —— 只写一边会在窄屏错位（宽屏看不出来）

**症状**（.21 多视口复验时发现）：1024 视口下列 [1]（标题）表头 256px、数据行 240px，
后面 11 列**整体左移 16px**；1280 / 1366 视口下却完全对齐。

**根因**：主题里 `tdSel(m,k)` 生成的是 **`R > td…`（只数据行）**，"片头"要用 `H > td…`。
标题列的 `max-width:max(240px, calc(100vw - 900px))` 原来只写在数据行 ⇒
- 1024 视口：上限 `max(240, 124)` = **240**，可用 **256** ⇒ 数据行被卡在 240、片头长到 256 ⇒ 差 16
- 1280 视口：上限 `max(240, 380)` = 380 > 可用 256 ⇒ 两边都是 256 ⇒ **看不出问题**

**修法**：新增 `hSel(m,k)`（片头列选择器），把这条 `max-width` **同时给两边**。

**教训**：
1. **片头与数据行是两条独立的 flex 行**，任何影响列宽的规则（flex-basis / min-width / max-width /
   padding）**必须两边都写**，只写一边就会错位。已有 `FILM_W` 那套 flex-basis 是两边都 push 的
   （`basis` 数组分别 push 到 H 和 R），所以要特别注意**后来单独加的规则**有没有漏掉片头。
2. **窄屏才暴露的 bug 要在多个视口复验**。这次 1280（默认）测了 3 轮都没发现，
   是加了 `HDUI_VW` 视口参数跑 1024 才暴露的 —— 单个视口的"全绿"不代表对齐是真的。
