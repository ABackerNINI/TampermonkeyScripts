> 摘要: 压平站点底色会连状态线索一起压掉 —— 记得用文字/字色补回来；中等亮度语义色块不在漏白扫描范围内（门槛 > 200）。

## P63. 压平站点底色会**连状态线索一起压掉** —— 记得用文字/字色补回来

**起因**：`.14` 加了 `td[bgcolor]{background:var(--hdui-panel)}` 抹掉站点的亮色块（那时是为了治
「顶部通知条亮黄块」）。但**进度指示器也是靠底色区分状态的**：

| 状态 | 站点底色 | 压平后 |
|---|---|---|
| 做种 | 青 `#44cef6` | 同一深色 |
| 下载 | 粉 `#CC0066` | 同一深色 |

⇒ 两种状态长得一模一样，**只剩文字能分辨**。这是"修 A 问题顺手把 B 的线索弄丢"的典型。

**为什么漏了这么久**：`#CC0066` 的亮度约 **73**，`#44cef6` 约 **161** ——
漏白扫描的门槛是 **> 200**，两者都**不在扫描范围内**，所以扫不出来。
（教训：**"不是白底"≠"没问题"**，中等亮度的语义色块要单独量。）

**修法**（`.23`）：底色压平后，用**文字颜色**把线索补回来 ——
`translateLeeching()` 在替换文字时顺便给格子打 `data-hdui-prog="seed"|"leech"` 标记，
CSS 按标记染字色（做种=绿 `#7fb84e` / 下载=琥珀 `#f5b342`）。

**两个实现要点**：
1. **认原词，别认替换后的中文** —— 标记要在**替换之前**根据 `Seeding`/`Leeching` 判定，
   否则重复调用（结构守卫会重试）时中文已经不是英文了，认不出来。
2. **必须连 `font` / `b` 一起染** —— 站点在 `<font color="#fff">` / `<font color="#FF0066">` 上
   写死了自己的 `color`，只染 `td` 会被子元素的声明盖掉（又一次"子元素声明压过继承"）。
3. 用 `data-*` 标记而不是 `td[bgcolor="#44cef6"]` 选择器：
   **认词语比认站点配色稳**，站点改配色不会连带弄坏这个。
