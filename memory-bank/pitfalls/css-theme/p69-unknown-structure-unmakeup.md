# 未知结构一律卸妆(2026-09-20 用户裁决)
> 摘要: 未知结构一律卸妆（2026-09-20 用户裁决）：认不出来的列/行不猜、直接回退原站界面，也不进等结构窗口。
> 触发: 未知结构, 一律卸妆, E_COLUMN_UNEXPECTED, E_ROW_UNKNOWN, 不进等窗口

- **触发**: 裁决：站点新增认不出来的列（`E_COLUMN_UNEXPECTED`）或认不出来的行（带 colspan 的分组/公告行，`E_ROW_UNKNOWN`）时，主题不猜，直接回退原站界面。
- **判别**: 为什么不是「照常上妆」：主题是「每列一个 `nth-child` 槽位」的排版，多出来的列/行没有槽位，硬上妆的结果只有两种 —— 被摆到错误的槽位，或被 `overflow:hidden` 压成一坨；两者都等于屏蔽未知元素，与「对未知元素不默认屏蔽」直接冲突，认不出来就把页面还给原站反而是最守底线的做法。
- **处置**: 为什么不进等结构窗口：`STRUCT_CODES`（会等 8 秒的那个）只留给 `ROW_CELL_COUNT_MISMATCH` —— 那是「A / A·GB 还没补完」的时序问题；未知列/未知行不是时序问题，等也没有用，拖 8 秒才报错只会让人以为脚本卡死（与 `E_COLUMN_UNKNOWN` / `E_ANCHOR_MISSING` 同一档）。

## P69. 未知结构一律卸妆(2026-09-20 用户裁决)

**裁决**: 站点新增**认不出来的列**(`E_COLUMN_UNEXPECTED`)或**认不出来的行**
(带 colspan 的分组/公告行, `E_ROW_UNKNOWN`)时, 主题**不猜**, 直接回退原站界面。

**为什么不是"照常上妆"**: 主题是「每列一个 `nth-child` 槽位」的排版。多出来的列/行没有槽位,
硬上妆的结果只有两种 —— 被摆到错误的槽位, 或被 `overflow:hidden` 压成一坨。**两者都等于屏蔽未知元素**,
与"对未知元素不默认屏蔽"直接冲突。认不出来就把页面还给原站, 反而是最守底线的做法。

**为什么不进等结构窗口**: `STRUCT_CODES`(会等 8 秒的那个)只留给 `ROW_CELL_COUNT_MISMATCH` ——
那是"A / A·GB 还没补完"的**时序问题**。未知列/未知行不是时序问题, 等也没有用,
拖 8 秒才报错只会让人以为脚本卡死(与 `E_COLUMN_UNKNOWN` / `E_ANCHOR_MISSING` 同一档)。
