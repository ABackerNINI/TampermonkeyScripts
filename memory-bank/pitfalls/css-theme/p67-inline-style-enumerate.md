# inline style 的兜底要**按写法枚举**, 漏一种写法就漏一块
> 摘要: inline style 的兜底要按写法枚举，漏一种写法就漏一块；`[style*='background:#fff']` 没覆盖 6 位写法 `background:#ffffff`，公告条/跑马灯留一块白。
> 触发: inline style, 按写法枚举, background #ffffff, 漏白扫描, INLINE_OK 清单

- **触发**: 主题有 `[style*='background:#fff']` 兜底，却没有 6 位写法 `background:#ffffff`；公告条 / 跑马灯最常写 6 位 ⇒ 底没被压深，留一块白。
- **判别**: 为什么两条扫描都抓不到：漏白扫描看的是背景亮度，对比度扫描看的是前景 vs 背景 —— 白底 + 黑字的对比度是满分，两条都判「没问题」；只有人眼能看出「这里有一块白」⇒「看得见」≠「没问题」，白底本身就是漏网，哪怕它上面的字看得清。
- **处置**: 把 `background` / `background-color` × `#fff` / `#ffffff` / `white` / `rgb(255,255,255)` × 带空格/不带空格全列一遍（与 .14 同一套路），新增一类写法时同步补；教训：按值枚举的兜底每补一种写法都要写进 `check-hdui-static.js` 的 INLINE_OK 清单，否则会悄悄退化。

## P67. inline style 的兜底要**按写法枚举**, 漏一种写法就漏一块

**症状**: 主题有 `[style*="background:#fff"]` 兜底, 却没有 6 位写法 `background:#ffffff`。
公告条 / 跑马灯最常写 6 位 ⇒ 底没被压深, 留一块白。

**为什么两条扫描都抓不到**: 漏白扫描看的是**背景亮度**, 对比度扫描看的是**前景 vs 背景** ——
白底 + 黑字的对比度是**满分**, 两条都判"没问题"。只有人眼能看出"这里有一块白"。
⇒ **"看得见" ≠ "没问题"**: 白底本身就是漏网, 哪怕它上面的字看得清。

**修法**: 把 `background` / `background-color` × `#fff` / `#ffffff` / `white` / `rgb(255,255,255)` ×
带空格/不带空格 **全列一遍**(与 .14 同一套路), 新增一类写法时同步补。
**教训**: 按值枚举的兜底, 每补一种写法都要写进 `check-hdui-static.js` 的 INLINE_OK 清单, 否则会悄悄退化。
