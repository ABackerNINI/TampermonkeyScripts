## P79. **别替站点重新设计它已经画好的东西** —— 促销徽章的三轮返工

**历程**(同一处东西改了三遍, 前两遍都被用户否掉):
- `.20` **图形徽章**: 把 `img.pro_*` 换成 16×16 主题图标 → 用户「Free 等促销标签不具辨识度」
- `.29` **文字徽章**: 把文字画进 SVG(Free / 50% / 2X Free) → 用户仍不满意
- **`.30` 站点原图**: **一条规则都不生成** → 用户要的就是这个

**为什么会连错两次**: 一直在"怎么画得更好"上使劲, 却没先问"**该不该我们画**"。
站点促销是 36×11 的雪碧图, 尺寸刚好、语义清楚; 我们换成的任何东西(图形或文字)
都是在**用自己的表达覆盖站点的表达**。

**判据: 什么该换、什么不该换**

| 情况 | 结论 | 真站例子 |
|---|---|---|
| 站点资源**尺寸/定位不匹配**当前布局 | **必须换** | 类别图标: catsprites 是 45×46 定位, 裁到 16×16 会碎 |
| 站点资源**尺寸刚好、语义清楚** | **不要动** | 促销图标: 36×11 雪碧图, `src` 是占位图、本体是 background |
| 站点资源在深色底上**看不见** | 换, 但保留语义 | 置顶行底色(换色不是换图) |

**三条纪律**:
1. **动手前先问"它现在能看吗、尺寸对吗"** —— 能看且尺寸对, 就别碰。
2. **"用户说看不清"不等于"要我们重画"** —— 也可能是**我们上次重画错了**,
   直接回退原图往往就是答案(.30 就是这么解决的)。
3. **改回原图时, 死代码要删干净**: `.30` 移除了 `promoBadgeUri` / `PRO_BADGES` /
   `PRO_FALLBACK_LABEL` / `PRO_FALLBACK_COLOR` —— 留着会误导后来者以为"促销还是我们在画"。

**改回原图最容易漏的两处配套**:
① **装饰扫描会误报**: `scanDeco` 会把保留的站点雪碧图当成"站点残留装饰 bg-img"
   (实测 33+27+9=69 个, 直接让真站验收变红) ⇒ 必须加白名单例外,
   与 `tr.sticky_top` 的 inset 金边同类 —— 都是"**刻意保留, 不是没清干净**"。
② **金丝雀契约要跟着降**: "未知图标必须换成主题 SVG"这条对促销不再适用,
   应降级为"没被压没"(尺寸 ≥8px); **类别**图标仍必须换 SVG(见上表第一行)。
   忘了改就会看到两个金丝雀用例红, 而且错误信息会指向错误的方向。
