# CSS 的失败是**静默**的：规则写错会被浏览器直接丢弃，不报错也不渲染
> 摘要: CSS 的失败是静默的：规则写错会被浏览器直接丢弃（不报错也不渲染），HDHomeUI 是纯 CSS 层，渲染结果类扫描发现不了「这条规则根本没生效」。
> 触发: CSS 静默失败, 死规则, CSSOM cssRules, 语法错误, 括号, 反向验证

- **触发**: HDHomeUI 全部效果靠往 `style#hdui-css` 塞规则，而 CSS 出错时浏览器是静默丢弃整条规则：不抛异常、不渲染、页面上只是「没变化」；前几轮加的四档扫描（漏白 / 小件近白 / 残留装饰 / 对比度）看的都是渲染结果，「这条规则根本没生效」这类问题它们照样发现不了。

## P57. CSS 的失败是**静默**的：规则写错会被浏览器直接丢弃，不报错也不渲染

**为什么这是本项目的头号隐患**：HDHomeUI 是**纯 CSS 层** —— 全部效果靠往 `style#hdui-css`
里塞规则。而 CSS 出错时浏览器是**静默丢弃整条规则**：不抛异常、不渲染、页面上只是"没变化"。
前几轮加的四档扫描（漏白 / 小件近白 / 残留装饰 / 对比度）看的都是**渲染结果**，
"这条规则根本没生效"这类问题它们照样发现不了。

**典型死法**：`TN_META + '{flex:0 0 auto'` 少一个 `}`；`statStack` 生成 `:nth-child(undefined)`；
`content:url(...)` 里 SVG 没转义；选择器拼出 `td[[[bad` 这种语法错误。

**检查手法（已固化成 `sim-hdui-css-validity.js`，第 29 个用例）**：
把 `style#hdui-css` 的文本按**顶层 `{}`** 切成一条条，逐条喂给一个临时 `<style>`，
用 CSSOM 的 `cssRules.length` 判断有没有被解析 —— CSSOM 会直接丢掉无法解析的规则，
所以「切出来 N 条」与「解析出 M 条」的差就是死规则，且能把原文打印出来定位。

真站实测：**251 条切出来、251 条解析、0 条丢弃**。
已**反向验证过**：故意塞一条 `html[data-hdui-theme] td[[[bad-selector{...}`，用例立刻红并把原文报出来。

**注意区分**：**无效的属性值不会让规则整条消失**（CSS 只忽略那一条声明、保留规则），
所以这个检查只抓「选择器/括号/语法」层面的错误，抓不到 `color:#zzz` 这种 —— 后者要靠渲染扫描。
