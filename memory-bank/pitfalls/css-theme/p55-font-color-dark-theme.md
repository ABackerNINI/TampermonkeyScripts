## P55. 深色主题最容易漏的一类：站点 `<font color>` 老式着色 —— 深蓝/暗红压在深色底上等于看不见

**症状**：底栏的分享率 / 魔力值 / 邀请 / 上传量 / 下载量 / 做种位 / 活跃全部「看不见」
（站点一律 `<font class="color_*">` + `#1900d1`），数据行里的红色标记同理（暗到 `#550000`）。
⚠️ **用户不会说"对比度低"，只会说"那个数怎么没了"** —— 靠截图很难定位，必须自动扫。

**根因**：主题管了 `#info_block` 与它的 `b` / `a`，但**没管站点自己用 `<font color>` 写死的颜色**。
这类老式着色是**元素自身的声明**，优先级高于任何继承，不显式覆盖就原样保留。

**修法**：
1. `font.color_*` 7 个类 → 各给一个色板里的可读色位（分享率金、魔力值琥珀、上传绿、下载红、
   邀请紫、做种位蓝紫、活跃青绿）。
2. 暗红 `<font color="#xxxxxx">` → **按值枚举**统一提亮成 `#e5705f`（保留"这是红色强调"的语义）。
   ⚠️ CSS 拿不到"站点原本那个色"（`currentColor` 是继承值，不是自身指定值），
   所以只能枚举 —— 漏一个值就漏一处暗字，靠扫描补。

**⚠️ 生成 CSS 时的坑**：7 个色**必须一条一色分开写**。图省事把 7 个选择器并成一条、
声明块里连写 7 个 `color`，**只有最后一个生效**（前 6 个被覆盖），7 个统计值会变成同一个色 ——
而这在语法上完全合法，静态检查看不出来。已在 `sim-hdui-film-fidelity` 加
「7 个统计值颜色两两不同」断言，并**验证过改坏会红**。

**⚠️ 静态断言要打在表上，不要打在拼接结果上**：这些 CSS 是运行时由 `INFO_COLORS` 拼出来的，
源码里**没有**字面串 `font.color_ratio{color:#f5b342}`，按拼接结果写正则必然误报（刚踩过）。

**排查手法（可复用）**：真站整页跑「对比度」扫描 —— 取**自带文本**的元素（直接子文本节点非空），
沿祖先找第一个不透明底色当有效背景，`|前景亮度 - 背景亮度| < 40` 就报。只报结构与颜色不报文本。
本次一轮扫出 24 处（6 类深蓝 + 一批暗红），修完剩 1 处（`#aa0000`，补进枚举表后清零）。
