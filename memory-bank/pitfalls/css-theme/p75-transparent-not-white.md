# **透明 ≠ 白** —— 漏规则会透出父级, 渲染扫描对它是隐形的
> 摘要: 透明 ≠ 白 —— 漏规则会透出父级，渲染扫描对它是隐形的；内层 `tr` 漏规则时是 `transparent`，透出的是外层已上妆的深色 card，两档扫描只看元素自身声明的背景亮度、抓不到声明缺失。
> 触发: 透明不等于白, 声明缺失, 分层计数, 具体色值断言, 结构断言

- **触发**: 用户再报「第二段置顶种子仍是白色背景」，但真站样本上 `tr.sticky_top` 86 个全部 `self=29` 深色、置顶验收 86/86、漏白与小件近白双双干净；把 `.25` 的修复 `TN + '.sticky_top{background:var(--hdui-card)}'` 删掉再跑，真站报告「共 86 个、透明 43 个」—— 而漏白 / 近白两条扫描依然报干净。
- **判别**: 内层 `tr` 漏规则时是 `transparent`，它透出的是外层那条已经上妆的深色 card，所以视觉上根本不是一块白；而两档扫描看的都是元素自身声明的 `background-color` 亮度（漏白 `lum > 200 且 area > 20000`、小件近白 `lum > 190 且 150 ≤ area ≤ 20000`），两者都只能抓「声明了亮色」，抓不到「本来该有底色、结果没有」这种声明缺失；后果：「某条规则漏了」这一类缺陷在整页渲染扫描里是隐形的 —— 扫描全绿不代表没有漏网的裸奔元素（P65 那条之所以漏了整整一个版本，正是因为 `theme-switch` 只验了 `sticky[0]` 外层的金色 inset，内层一个断言都没有）。
- **处置**: 四条纪律：① 断言要验到具体色值，不要只验「非透明」或「存在」—— `sim-hdui-sticky-nested.js` 直接比对 `rgb(32, 28, 24)`（= `--hdui-card`），只写「不等于 rgba(0,0,0,0)」会被「站点给自己上了另一个色」蒙混过关；② 同 class 出现在多层时必须分层计数（外层 `R` / 内层 `TN` 分开），不能只取 `[0]` —— 真站 `tr.sticky_top` 86 = 外 43 + 内 43，取 `[0]` 永远只看得见外层那一半；③ 前置断言「夹具真的造出了两层结构」（用例开头先断言 `outer.length > 0 && inner.length > 0`），否则夹具一改整个用例就变成空跑（与 P74-2 同源）；④ 渲染扫描的覆盖面 = 「元素自身声明了什么」不是「元素该有什么」—— 要抓漏规则只能靠按选择器主动点名（`verify-hdui-real-page.js` 那条 86/86 就是这么来的）；附带（P72 的又一个实例）：`.25` 那条静态断言用跨行通配正则几乎恒真，把修复整条删掉它也不红（实测证实）等于没有断言，已改成三条严断言并各自反向验证（写完断言必须做一次反向验证，见 P72）；配套的「第三层」防线：`all === byR + byTN 且 neither === 0`（真站实测 86 = 43 + 43、both=0、neither=0）验的是 DOM 结构不是 CSS 覆盖，删 CSS 不会让它变红 —— 反向验证要注入一个合成的同 class 嵌套行（实测注入后 `neither` 0 → 1，确认可证伪）。

## P75. **透明 ≠ 白** —— 漏规则会透出父级, 渲染扫描对它是隐形的

**怎么发现的**: 用户再报「第二段置顶种子仍是白色背景」。但真站样本上
`tr.sticky_top` 86 个**全部 `self=29` 深色**、置顶验收 86/86、漏白与小件近白**双双干净**。
把 `.25` 的修复 `TN + '.sticky_top{background:var(--hdui-card)}'` **删掉**再跑,
真站报告「共 86 个, **透明 43 个**」—— 而**漏白 / 近白两条扫描依然报干净**。

**为什么**: 内层 `tr` 漏规则时是 `transparent`, 它透出的是**外层那条已经上妆的深色 card**,
所以视觉上**根本不是一块白**。而两档扫描看的都是**元素自身声明的 `background-color` 亮度**:
- 漏白: `lum > 200 且 area > 20000`
- 小件近白: `lum > 190 且 150 ≤ area ≤ 20000`

两者都只能抓「**声明了亮色**」, 抓不到「**本来该有底色、结果没有**」这种**声明缺失**。

**后果**: 「某条规则漏了」这一类缺陷, 在整页渲染扫描里是**隐形**的 ——
扫描全绿不代表没有漏网的裸奔元素。P65 那条之所以漏了整整一个版本, 正是因为
`theme-switch` 只验了 `sticky[0]`(外层) 的金色 inset, 内层**一个断言都没有**。

**四条纪律**:
1. **断言要验到具体色值**, 不要只验「非透明」或「存在」——
   `sim-hdui-sticky-nested.js` 直接比对 `rgb(32, 28, 24)`(= `--hdui-card`),
   只写 `!== "rgba(0, 0, 0, 0)"` 会被「站点给自己上了另一个色」蒙混过关。
2. **同 class 出现在多层时必须分层计数**(外层 `R` / 内层 `TN` 分开), 不能只取 `[0]` ——
   真站 `tr.sticky_top` 86 = 外 43 + 内 43, 取 `[0]` 永远只看得见外层那一半。
3. **前置断言「夹具真的造出了两层结构」**: 用例开头先断言 `outer.length > 0 && inner.length > 0`,
   否则夹具一改整个用例就变成空跑(与 P74-2 同源)。
4. **渲染扫描的覆盖面 = 「元素自身声明了什么」, 不是「元素该有什么」** ——
   要抓漏规则, 只能靠按选择器**主动点名**(`verify-hdui-real-page.js` 那条 86/86 就是这么来的)。

**附带(P72 的又一个实例)**: `.25` 那条静态断言
`ok(/table\.searchbox[\s\S]*TN.../.test(src) || /\bTN \+ '\.sticky_top\{background.../)` ——
`[\s\S]*` 跨行通配几乎恒真, **把修复整条删掉它也不红**(实测证实), 等于没有断言。
已改成三条严断言并各自反向验证。**写完断言必须做一次反向验证**, 见 P72。

**配套的「第三层」防线**: 只断言"背景不为透明"能证明**当前这 86 个都盖住了**,
证明不了**没有第三层** —— 站点若在别处再嵌一层同 class 的表, 那批元素既不匹配 `R` 也不匹配 `TN`,
会重新裸奔(而扫描依旧抓不到)。所以 `verify-hdui-real-page.js` 加了一条**结构**断言:
`all === byR + byTN 且 neither === 0`(真站实测 86 = 43 + 43, both=0, neither=0)。
⚠️ 这类断言验的是 **DOM 结构不是 CSS 覆盖**, 删 CSS 不会让它变红 ——
反向验证要**注入一个合成的同 class 嵌套行**(实测注入后 `neither` 0 → 1, 确认可证伪)。
