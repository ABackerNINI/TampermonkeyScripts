# AI 协作纪律：计划阶段改码 / 未审核即提交
> 摘要: 计划/分析任务不得改码，实施任务完成后须汇报等审核，提交一律由用户执行。
> 触发: 让 AI 做方案, 让 AI 改码, 提交前, 审核改动

- **触发**: 让 AI「做个方案/分析」，结果它直接改了代码；或让 AI 改完代码，它顺手 `git commit` / `git push` 了。
- **判别**: AI 未区分「计划」与「实施」的任务边界，或把「完成修改」误当「可以提交」。
- **处置**: 计划/分析类任务：只输出方案，**不改任何代码文件**；确需改码才能得出结论时先停下征询用户。实施类任务：修改完成后**汇报改动并等待用户审核**，`git commit` / `git push` 一律由用户执行或明确指示。该纪律为最高优先级约定，详见 `memory-bank/conventions.md` 第 0 节「核心铁律」。

## P13. AI 协作纪律：计划阶段改码 / 未审核即提交

**症状**：让 AI「做个方案/分析」，结果它直接改了代码；或让 AI 改完代码，它顺手 `git commit` / `git push` 了。
**原因**：AI 未区分「计划」与「实施」的任务边界，或把「完成修改」误当「可以提交」。
**正确做法**：
- 计划/分析类任务：只输出方案，**不改任何代码文件**；确需改码才能得出结论时先停下征询用户。
- 实施类任务：修改完成后**汇报改动并等待用户审核**，`git commit` / `git push` 一律由用户执行或明确指示。
- 该纪律为最高优先级约定，详见 `memory-bank/conventions.md` 第 0 节「核心铁律」。
