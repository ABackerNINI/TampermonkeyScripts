PTAutoCheckIn FAB 皮肤精简与靠边模式改造（含静息 CPU 修复）

§01目标与设计原则

目标 — 一次改造同时交付三件事：① 皮肤条从 4 选 1 收敛为「变色 / 信号灯 / 静态」3 选 1，删掉数字与光环；② 新增与皮肤正交的「靠边模式」——最小显示为右下角静态竖线、颜色跟随当前状态色、鼠标移入展开为原 FAB、移出恢复靠边；③ 从根上消除上一轮确认的静息态 CPU 高占用（非合成属性 infinite 动画逐帧全链路重绘）。成态判据：默认状态下不操作也不再持续触发 Recalculate Style → Pre-Paint → Paint → Composite 全链路；签到核心逻辑（UNITS / 批量调度 / GM 状态 / 面板交互）行为零漂移。

不变量（硬约束）:

  1. 本轮零实施 — 本篇是计划；不改代码、不入池 issue、不认领、不 commit/push。实施须用户逐项授权（新建文件 / 入池 / 认领 / commit 四类动作分别确认）。
  2. 核心逻辑零改动 — 签到、批量、冷却、重试、favicon、状态判定、后台页不注入 UI 等一律不碰；改动面只在 UI_CSS 的 FAB/皮肤条段、FAB 构建/皮肤应用/渲染段、GM 键表与新增开关处理。
  3. 用户拍板为准 — §06 的 D1–D12 是决策单点；实施中若出现未覆盖的歧义，回到用户拍板，不自行假设。
  4. 版本与知识库同步 — 实施轮每批改任何脚本/元数据必须同批递增脚本头 @version（YYYY.MM.DD.N，跨天重置 N）并回写 memory-bank/ 受影响条目（项目铁律 3/4）：scripts/PTAutoCheckIn/fab-ui.md、overview.md、坑档 P17（皮肤语义）、conventions/known-issues.md；本批只写方案文档，无脚本改动故不触发。
  5. 测试护栏保持 — test.full 全绿；新增静态断言与仿真用例随实现同批落地，测试基线数字只写 testing/baselines/ 新切片。

取舍口径（源自 grilling）：性能修复不等同于「加开关让用户自己关」——长期装机脚本必须默认无感修复，开关是显式兜底而非责任转嫁；靠边与皮肤正交，因此竖线颜色直接复用当前皮肤的状态色语义，不另立规则。

§02现状与痛点

UI 现状（只读实测，行号对应 src/PTAutoCheckIn.user.js @version 2026.11.19.3）：

  • FAB 为 <button class="fab">（第 2640–2641 行），挂在 attachShadow({mode:'closed'}) 内（第 2634 行）——外部 CSS 无法穿透。交接文档给的 document.head.appendChild(style) 止血法对 closed shadow 无效，这正说明脚本内置开关是必需能力，不是锦上添花。
  • 皮肤 4 套：chameleon（默认）/ number / signal / ring，存 GM 键 ptac_skin（第 102 行），皮肤条在面板头部「外观」展开（第 2665–2671 行），点击走 setSkin（第 2796–2801 行）。
  • applyFabSkin（第 2805–2878 行）按 skin 分支改 class / innerHTML / 角标；default 分支即变色（第 2867–2872 行），天然兜底未知 skin 值。

CPU 根因（上一轮已确认，本篇据此修）:

证据实测结论
交接件 Performance 火焰图层根元素 button.fab.chameleon，约 8ms 一拍，链路「画图 → 分层 → 提交 → 计划样式重新计算 → 重新计算样式 → 预绘制」——含 Recalculate Style，说明是逐帧改非合成属性，不是纯 transform/opacity 合成层动画
baseGlow / stateGlow（第 2214–2217、2235–2238 行）infinite 动画改 box-shadow，每帧 Paint
chameleonWave（第 2247–2253 行）infinite 动画改 transform + border-radius，其中 border-radius 非合成 → 每帧 Recalculate Style + Pre-Paint；变色皮肤同时挂两条动画（第 2243–2244 行）
定时器扫描（全文）所有 setInterval 为 200ms/1000ms（第 1862、2996 行），唯一 setTimeout 最短 200ms；无 8–16ms 定时器、无 requestAnimationFrame、无写样式的 MutationObserver 回环——排除交接文档的定时器猜测
交叉排除（交接件）关闭 ptskit-farm-helper 与屏蔽统计脚本后 CPU 仍高；本脚本 @match *://*.ptskit.org/*（第 39 行）正好覆盖拾刻农场页，是注入该页的外来 FAB

8ms 更可能是高刷屏帧节奏或两个不同周期动画（3.6s + 3.2s）错相叠加的采样间隔，不是人为定时器；不影响定性——元凶是 infinite 非合成属性动画本身。

§03方案总览

主线一句话 — 把 FAB 的动效从「JS 改非合成属性」的旧写法整体换成合成器友好写法（辉光走 opacity 伪元素、形变只留 transform），同时把皮肤条收敛为 3 项并把「靠边」作为正交开关塞进同一条皮肤条，用一个新 GM 键 ptac_edge 跨站记住靠边态。

批次内容对应拍板验收法
A · 性能修复A1 baseGlow/stateGlow 改为预渲染光晕伪元素 + 只动 opacity；A2 chameleonWave 去掉 border-radius 波动、只留 transform；A3 随数字/光环删除同步清掉 numPulse/ringBreathe/rayPulse 与射线 DOM 生成D1 · D12静态检查断言无 infinite 动画改 box-shadow / border-radius / filter；Performance 录 5s 静息，Recalculate Style 事件不再按帧出现
