§05根因（可选）

已排除：当轮代码改动（批次未触 JS）；浏览器缺失、样本缺失（SKIP 门禁未触发）。
高置信假设（待复验）：默认样本路径下的真站整页样本为旧版存盘，站点此后改版，页面结构与 HDHomeUI 预期锚点（table.mainouter 等四处）不再相符 —— 修复需用户重新另存当前真站整页（私有资源，agent 不自制样本），属用户侧动作，故先入池。
〔2026-11-17 复验推翻上述假设〕真实根因：样本并没有过期 —— 四个锚点在样本活标记里全部存在（非注释/CSS 文本）。实测链（探针取证 2026-11-17 03:xx 前后）：① 复刻测试驱动的静态服务器+Chrome，导航 http://hdhome.org/torrents.php 得到空文档（outerHTML 仅 39 字符），锚点全缺 → HDHomeUI 结构守卫卸妆报 E_ANCHOR_MISSING；② Page.navigate 返回 errorText: "net::ERR_BLOCKED_BY_CLIENT"，本地服务器零请求命中；③ 拦截面为「公网域名 + 明文 http」：hdhome.org/example.org/example.com/gitee.com 全被拦，hdhome.test/foo.invalid 正常；④ 直连 127.0.0.1:<port> 同一样本完整渲染、四锚点全中（docLen 397120）；⑤ 启动参数补 --disable-features=HttpsUpgrades,HttpsFirstBalancedModeAutoEnable,HttpsFirstBalancedMode 后全部域名立即正常。结论：本机 Chrome 自动更新后默认启用 HTTPS-First 升级，公网域名 http 导航强制升 https、撞本地纯 HTTP 静态服务器失败后 http 回退再被客户端拦截 → 空文档误判卸妆。深层原因：verify-hdui-real-page.js 自带 launch() 未复用 tests/lib/sim/harness.js 的启动参数（后者已带 --disable-features=HttpsFirstBalancedMode,TranslateUI，但清单也缺新版 feature 名），Chrome 默认行为变化后暴露。

§06建议修法（可选）

  • 主路：用户重新另存一份当前真站整页覆盖默认样本路径的旧样本（仍留私有目录、不入 Git、注意铁律 5），重跑 node tests/hdhomeui/verify-hdui-real-page.js 确认四处锚点全中、用例转绿。
