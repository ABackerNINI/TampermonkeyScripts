§01现象与发现场景

2026-11-19 排障用户报告「签到成功但仍显示未确认」时的伴生发现: Railgun 两步签到流程(首步 function 展开头像用户卡, 次步 CLICK_CHECK_IN 点横幅)存在跨步骤间隙 —— 首步轮询到横幅可见(getClientRects>0)+ sleep 300ms 后返回, 次步 waitForElement(unit.checkInSelector) 重新查询同一元素并要求可交互。真站(站点 topbar.js 管理开合)的卡片不保证在这段间隙里保持展开: 一旦收起, 横幅回到 display:none, 次步等满超时(约 5s + 慢页加成)后 reject, 按引擎「含超时→unconfirmed」口径记「未确认」, 该次点击未发生。

触发场景(候选, 见 §05): 被动模式下用户真实鼠标移开头像区 → 站点 mouseleave 监听 220ms 延迟收起(处置第④条「不派发 mouseleave 就不收」只防住合成事件, 防不住真实指针); 不排除站点在 open 时即 arm 带其它条件的自动收起。批量后台标签(无真实鼠标)同间隙是否收起未实证。

§05根因（可选）

部分确认: 展开态不保证跨步骤保持(真站 2026-11-19 实证一次失败 + 一次成功, 非确定性)。收起的具体触发条件待查 —— 已排除: 合成 mouseenter 自身触发收起(失败运行里首步可见性轮询曾通过); 待实证: ①被动模式真实鼠标 mouseleave→220ms 收起 ②站点 open 时 arm 的自动收起(如 :hover 校验式/重渲染抹掉注入的 .is-open)。需真站 topbar.js 复核。

§06建议修法（可选）

展开与点击原子化: Railgun 步骤合为单个 function 步 —— 展开(mouseenter + .is-open 兜底)→ 轮询横幅可见立即复用引擎守卫并点击(不留 300ms/步骤间隙), 失败重展开重试 3 次。需引擎小改: ①step.func(unit) 传入 unit; ②function 步骤可返回 {alreadyHit, refused} 标记(向后兼容, 现返回值被丢弃); ③把 click_checkin 的已签文案/内容校验/站外 href 守卫抽成共用函数, 两处复用不漂移。配合: 步骤 budgetMs 重声明(3×2500+余量) + tests/check-ptac-budget.js 过检。替代方案(否决): 首步内起 keepAlive 定时重assert 展开态 —— 无点击跟随(如已签短路)时卡片会在页面上反复弹开数秒, 被动模式观感差。

修复后补充

实际修法（采纳 §06 建议方向，三件引擎小改全部落地）：

  • 守卫抽取：click_checkin 的三重守卫（已签文案 / checkInContent 校验 / 站外 href）抽成 guardCheckInEntry(unit, el) 共用函数，原步骤与原子步两处复用不漂移；文案不匹配分支返回 {mismatch:true}，click_checkin 内语义与旧口径一致（不点不标）。
  • function 步契约：签名改 func(unit)（传 unit），可返回 {alreadyHit}/{refused} 标记并由 executeStep 向上传导（HHCLUB/NodeLoc 旧 function 步返回值仍丢弃，向后兼容零改动）。
  • Railgun 原子步：展开（mouseenter + .is-open 兜底）→ 轮询横幅可见（getClientRects>0）→ 守卫 → 立即点击合为单 function 步，无 300ms 动画 sleep、无跨步骤间隙；横幅未现重展开重试 3 轮；已签横幅（今日已签到）经守卫识别 alreadyHit 记成功。保留替代方案否决理由：keepAlive 重 assert 展开态无点击跟随时卡片反复弹开，被动模式观感差。

与建议修法的差异：无改道。§06 的「复用引擎守卫并点击（不留 300ms/步骤间隙）」按字面落地——连成功路径上的 300ms 卡片动画 sleep 也一并去除（可见即可点，横幅 display:none 时隐藏元素点击本就不触发导航，无需等动画）。

验证方式与测试数字：① node tests/ptautocheckin/check-ptac-budget.js 全绿（A1–A6/B1–B6/C1–C2/D1–D2；C1=3 个 function 步均声明 budgetMs，Railgun 声明 7500 = 3×2500，无 300ms sleep 后相应收紧）；② commands run test.full 全量 37/37 通过；③ node --check 语法冒烟通过。预算表：Railgun 检测 0 + 步骤 7500 + 预留 18000 = 25500/40000ms（余量 14500ms）。
